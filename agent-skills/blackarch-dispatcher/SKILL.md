# Blackarch dispatcher

- Flattened execute subcommands live in /opt/blackarch/bin/blackarch via _exec_cmds.
- New top-level commands only appear in `blackarch --complete` if registered in GROUP_DESCRIPTIONS (blackarch_core.py); unregistered commands still run via module import or bash fallback but stay invisible to completion.
- Autocomplete via --complete includes flattened list.
- Window ring is single-file rotating list; swap rotates first->last, focuses first.
- Audio dispatch supports -h/--help.
- USB SD-card reader (STORAGE DEVICE) skipped in disk selection.
- Installer: ask_yesno defaults to True; abort on partition prompt falls back to --existing; sysctl userns removed from installer; flatpak install uses --noninteractive; kodachi setup enabled by default (skip via --skip-kodachi); smartthings CLI installed via npm; USB SD-card reader (STORAGE DEVICE) skipped in disk selection.
- Execute: setup-post runs flatpak ulaa, creates blackarch-webapp.desktop (via sudo_write), sets xdg defaults, runs ipu6 webcam if /dev/video0, runs TPM setup, kodachi setup.
- setup-post is a group subcommand (`blackarch setup post`): it needs an executable `bin/blackarch-setup-post` for dispatcher discovery; the `blackarch_modules/blackarch_setup_post.py` module alone is not enough.
- Installer: `--efi-entry` removed; EFI boot entry is created only when `--bootloader` is given.
- Installer: `blackarch installer --gui` launches a PySide6 module (`blackarch_installer_gui`) that runs `sudo blackarch installer ...` and exposes all installer flags including `--skip-copy-sudoers`.
- Module naming: heavy logic modules are `blackarch_core_<domain>.py` (blackarch_core_execute, blackarch_core_installer) and live in `/opt/blackarch/blackarch_modules/`. When renaming one, update every importer: bin/blackarch, blackarch_core.py (MODULE_COMMANDS + the installer import), the thin alias modules (blackarch_execute.py, blackarch_installer.py), blackarch_installer_gui.py, blackarch_setup_post.py, README.md, and the agent skills.
- `bin/blackarch`'s fallback for unported commands must exec the resolved `bin/blackarch-*` file directly (its shebang picks the interpreter) and must build the name from the longest matching argv PREFIX, never the whole argv: joining every argv word made the name miss whenever flags were present, and forcing `bash` mis-executed Python scripts (`blackarch xdgmenu to quickshell` died on its own docstring).
- XDG menu generation: `blackarch_modules/blackarch_xdg_menu_generator.py` (routes `blackarch xdg menu to jsonc` and `blackarch xdgmenu to quickshell` are thin wrappers) evaluates `/etc/xdg/menus/*.menu` specs against the desktop entries and writes the flat JSONC map MenuModel.js consumes. `bin/blackarch-xdg-menu-parser` is an unfinished helper, not a command.
- A module under `blackarch_modules/` whose name matches a `blackarch <words>` route is captured by the dispatcher's generic runner and handed the trailing words as arguments: naming the generator `blackarch_xdg_menu` made `blackarch xdg menu to jsonc` resolve to the module and fail with `unrecognized arguments: to jsonc`. Heavy non-command modules use an infix no route can form (`_core_`, `_generator`, `_helpers`).
- `blackarch shell generate` (`quickshell_dispatch` -> `generate_menu()`) writes one JSONC per source into `default/blackarch/menus/`: each XDG menu definition (`<stem>.jsonc`, ids nested under `blackarch.`), `pentest.jsonc` (`blackarch.pentest.*`) and `smartthings.jsonc` (`smartthings.<uuid>`). The old single `additional-menu.jsonc` aggregate is deleted. The shell's menu plugin globs `menus/*.jsonc` with a bash `Process` (Quickshell 0.3.2 has no `dirContents`), concatenating files with `===<path>===` / `=== EOM ===` markers; a directory `FileView` re-runs the scan on change. The smartthings widget reads `menus/smartthings.jsonc`.
- The shell's menu FileViews reload asynchronously, so a menu opened in the same instant as a regenerate can show stale or empty content; wait a moment and reopen (or `blackarch menu refresh` then reopen) before judging.
- Menu loading/debugging depth (Quickshell glob pattern, restart-vs-refresh, hidden-branch debugging): `references/menu-loading.md`.
- `--menu` accepts several files (`action="extend"`, `nargs="+"`). With ONE file the root keeps `--root-id` (default `applications`) and the file's own `<Name>`/`.directory` label; with SEVERAL files each file becomes its own top-level menu whose id is the file stem (`red-applications`) and whose label is the humanized stem (`Red Applications`), with that file's submenus nested beneath. Same-named categories across files are NOT merged in multi-file mode.
- `<Move>` resolution in multi-file mode uses a union index of every menu from every input file, keyed by `<Name>` AND by its `.directory` label (xfce's `Network` is displayed as `Internet`). A move whose source is not in the file's own tree is CLONED in from the index, so the other file's tree is untouched. `<New>` is the moved node's full new path: only the parent part is created, the last component is the node's name.
- In single-file mode with `<DefaultMergeDirs/>`, `<MergeFile>` and `<MergeDir>` are still merged by name, and same-named menus UNION their Include rules; when both sides are `OnlyUnallocated`, an Include-free side wins (it already claims everything unallocated).
- In multi-file mode, a file named explicitly on `--menu` is emitted as its own root, so it is SKIPPED when `<DefaultMergeDirs/>` would pull it in implicitly (xfce's root merges `/etc/xdg/menus/applications-merged/*.menu`, which contains both `zam-plugins.menu` and `X-BlackArch.menu`; without the skip, a file listed on the command line appears twice). `load_merges` takes an `explicit` frozenset of resolved paths for this.
- MenuModel.js `normalizeItem` accepts an optional `kind` plus `appIcon`/`appId`; generated rows use `kind:"app"` so the menu renders the real image icon, launch feedback and uninstall path from AppLibrary instead of a text glyph. The fallback inference (`action` -> action, `target` -> link) is unchanged, so older menus and unpatched shells still work.
- `kind:"app"` rows are launched by `AppLibrary.launch()` -> `gtk-launch <appId>.desktop`; their `action` field is NEVER executed. A row that must run a blackarch command is a plain action row (omit `kind`), or it needs a real `.desktop` whose `Exec` is that command.
- A row's parent comes from its id prefix (`a.b.c` -> `a.b`) unless an explicit `parent` is set. The parent must exist AND be kind `menu`/`link`: `rebuildDisplay` filters `child.parent === active` and `isVisible` only walks children of the active menu, so a row under a missing or action-kind parent never renders. Only root children are top-level.
- Rows hand-added to `default/blackarch/menus/*.jsonc` are wiped by the next `blackarch shell generate`; the generator emits one row per `~/.local/share/applications/*.desktop`. Add a desktop entry for a durable custom row.
- Verify a new or edited row against the real parser before trusting it: `scripts/verify-menu-row.js <menu.jsonc> <row-id>` loads `shell/plugins/menu/MenuModel.js` in node and reports kind, parent, parent kind, visibility with `when:` true/false, and the guard line.
- When scripting an edit to menu JSONC, assert every `indexOf`/`find` result is not -1 before splicing, and write glyphs as a single-backslash `"\uf0372"` (a double backslash lands as literal `\\uf0372` text). An unused -1 index silently rewrites an unrelated earlier key.
- The menu plugin draws `icon` as TEXT (`Text { text: row.icon }`), so a themed icon name from a `.directory`/`Icon=` field renders as literal text. Use a nerd-font glyph; `CATEGORY_ICONS` in the generator holds the ones already used by blackarch-menu.jsonc.
- `generate_menu()` collapses X-BlackArch's redundant single "BlackArch" wrapper submenu (`_hoist_single_submenu`), so its categories sit directly under `blackarch.x-blackarch`.
- The generator itself (`generate()`, and therefore `blackarch xdg menu to jsonc`) keeps each menu's file-stem root at the TOP level; only `generate_menu()` re-nests those ids under `blackarch.` when writing the per-source files. Don't "fix" the CLI output to match the shell files.
- `MenuModel.mergeAppRows` must only swap rows whose parent is `apps`; dropping every `kind:"app"` row wiped the generated XDG app rows, leaving their categories empty and hidden (`isVisible` then hides the whole branch).
- XDG menu spec traps: the document element IS `<Menu>` (use `root if root.tag == "Menu" else root.find("Menu")`, never a bare lookup), multiple rules inside `<Include>`/`<Exclude>` are OR'd (Development = `<And><Category>Development</Category></And>` PLUS `<Filename>emacs.desktop</Filename>`), and `<DefaultMergeDirs/>` pulls in `/etc/xdg/menus/applications-merged/*.menu`.
- `blackarch_modules/blackarch_menu.py` `select_socket()` must skip sockets whose pid is dead: a killed shell leaves its socket directory behind, and the first stale entry wins, so every `blackarch menu ...` command fails with "blackarch-shell is not running" until the dead directories are removed.
- AppLibrary.launch(appId, name) runs `gtk-launch <appId>.desktop`, so `appId` must be the desktop-file-id WITHOUT the .desktop suffix (e.g. `org.telegram.desktop`, not `org.telegram.desktop.desktop`).
- Installer: `bootstrap_pacman()` copies the host pacman.conf + mirrorlists, then injects blackarch/athena/chaotic-aur/garuda repo entries and downloads their mirrorlists if missing.
- Installer: remove options --webcam-setup, --skip-kodachi; unlock default password.
- Setup: `blackarch setup` with no arg prints help; existing all-in-one behavior moved out.
- Flatpak: `blackarch flatpak-ulaa` command added.
- Module-backed commands: commands with no `bin/blackarch-<name>` executable (private, work, webapp, flatpak-ulaa, window, focus, gui, tui, vpn, update, update-system, brightness, audio, charger, banner, quickshell) are listed in MODULE_COMMANDS in blackarch_core.py; `dispatch_module()` imports `blackarch_modules.<module>` and calls its `main(argv)` with the FULL argv, because blackarch_core_execute reads its subcommand from argv[0]. Register every new flattened route there or it dies with `Unknown Blackarch command` (exit 127).
- `bin/blackarch` also keeps its own duplicate `_exec_cmds` flatten list; a route must be added in BOTH places (MODULE_COMMANDS and the wrapper list, plus the `--complete` list) or it stays unreachable.
- blackarch_core_execute `main()` treats every argument as real input, so `blackarch <cmd> --help` must be intercepted before calling it; the wrapper prints `print_help()` instead, and `dispatch_module()` prefers the module's own `print_help`.
- launch(id_kind="private") must splat the browser (`*browser`, not `browser`): `browser` is already a list from shlex.split, so passing it whole makes os.execvp raise `TypeError: expected str, bytes or os.PathLike object, not list`.
- A bare `except Exception: pass` around the execute-module import in `bin/blackarch` hides these failures and lets the core dispatcher print `Unknown Blackarch command`; when a flattened command misbehaves, reproduce the import and call manually to see the real traceback.
- SmartThings: `blackarch smartthings install|menu|status|value|widget` and device toggle; menu uses `blackarch toggle smartthings`.
- Installer: ulaa flatpak removed from installer; webcam setup opt-in; sysctl userns removed; flatpak install uses --noninteractive.
