## When to Use
- Analyzing whether a Linux tool or script from one distro works on another
- Adapting Debian/Ubuntu packages or scripts for Arch Linux
- Checking binary (ELF) compatibility across distros
- Planning phased migration of distro-specific components
- Porting a bash launcher/tool to Python (see `references/bash-to-python-porting.md`)
- Building a selector that groups several related one-shot installers behind one CLI
- Building a single dispatcher over a whole tree of ported commands (see `references/command-family-dispatcher.md`)

Use when analyzing and adapting Linux tools, scripts, or distro-specific packages from one distribution to another (e.g., Debian/Ubuntu to Arch). Covers cross-distro binary compatibility, package/path mapping, and phased migration planning.

## Workflow

1. **Inventory** — List the tool directory structure, identify binaries (ELF vs scripts), config files, and hook scripts.
2. **Binary compatibility check** — For each ELF binary: `file <path>` to determine linking (static vs dynamic), then `ldd <path>` to list shared library dependencies. Static-pie and fully static binaries are portable; dynamic binaries need libraries present on target distro.
3. **Library resolution** — For dynamic binaries, map each `lib*.so` to the target distro's package. Use `pacman -Ss <name>` on Arch. Check if the exact soname is satisfied with `ldconfig -p | grep <lib>`.
4. **Identify breaking points** — Scan scripts for: package manager calls (apt-get vs pacman), hardcoded paths (/usr/sbin vs /usr/bin on merged-/usr distros), distro detection files (/etc/os-release, /.debian-live-build, /var/lib/dpkg), init system differences, boot tool differences.
5. **Map alternatives** — Build a replacement table: package names, binary paths, config paths, service names. See `references/debian-to-arch.md` for the standard mapping.
6. **Test binaries** — Run each binary with --version or no args. Static binaries should work immediately. Dynamic binaries may need library packages installed first.
7. **Plan phases** — Group changes into: Phase 1 (deps + binary test, low effort), Phase 2 (script rewriting, medium), Phase 3 (boot/init integration, high). Present plan, get approval, execute.

## Key Principles

- **Working setup reference (read-only):** `/run/media/black/luks-04244121-3fee-4ce4-a0ca-2217d37faa1d/blackarch` holds a working setup that may be consulted for troubleshooting, but it must never be modified.
- **Ported code lives only in `/opt/blackarch`.** `config/` and `default/` are real directories (not symlinks). `old_repo` is scheduled for deletion, so do not reference it in new ports or documentation — resolve anything needed from `/opt/blackarch` directly before it is removed.
- **No deletion without explicit confirmation** except within the designated workspace; `.bash-orig` backups may be removed only once a Python port exists.
- `/usr/sbin` vs `/usr/bin`: Debian keeps them separate; Arch uses merged `/usr`. Create symlinks if scripts reference `/usr/sbin/` paths.
- Boot tools differ significantly: dracut/initramfs-tools (Debian) vs mkinitcpio (Arch). These are the hardest to port.
- Package manager scripts must be fully rewritten — there is no drop-in apt-to-pacman translation.
- systemd service units are generally portable; only paths inside ExecStart need fixing.

## Pitfalls

- `ldd` on a binary compiled for a different distro may show libraries at different soname versions. Verify with `ldconfig -p | grep <lib>` on the target.
- Static-pie binaries run anywhere but may still assume `/etc/` layout, systemd unit locations, or DBus service names.
- Don't rewrite every hook script — test each individually. Many bash scripts are distro-agnostic.
- GUI binaries fail with "cannot open display" in headless environments — that is expected, not a compatibility failure.
- When creating symlinks for `/usr/sbin` -> `/usr/bin`, these require root. Ask the user before running sudo commands.
- `dpkg -l` output format is incompatible with `pacman -Q` — scripts that parse dpkg output (grep for `^ii`, awk columns) need full rewrites, not sed replacements.
- `DEBIAN_FRONTEND=noninteractive` has no pacman equivalent — use `--noconfirm` flag instead.
- Many Debian packages are AUR-only on Arch (v2ray, xkcdpass, ttf-ms-fonts, etc.) — detect AUR helper (yay/paru/trizen/pikaur) and split install into official + AUR phases.
- `apt-transport-tor` is Debian-only — no Arch equivalent exists. Skip it.
- **xdg-mime handlers for webapp URLs:** create `~/.local/share/applications/blackarch-webapp.desktop` with `Exec=/opt/blackarch/bin/blackarch execute webapp %u` and `MimeType=x-scheme-handler/http;x-scheme-handler/https;`, then `xdg-mime default blackarch-webapp.desktop x-scheme-handler/http` (and https). Expose as `blackarch execute setup xdg-mime`.
- `systemd-resolved` is part of the systemd package on Arch — do not try to install it separately.
- `tor-geoipdb` is bundled with the tor package on Arch — no separate package needed.
- `build-essential` is a Debian metapackage; on Arch use the `base-devel` group.
- `lib*-dev` packages (e.g. `libxcb1-dev`, `libxcb-xkb-dev`) map to the base library package on Arch (e.g. `libxcb`) — there is no separate -dev package.
- `resolvconf` is replaced by `openresolv` on Arch.
- `cryptsetup-initramfs`, `cryptsetup-nuke-password`, `unattended-upgrades`, `ram-wipe` are Debian-only — skip them on Arch.
- `rng-tools-debian` → `rng-tools` on Arch (drop the `-debian` suffix).
- `ttf-mscorefonts-installer` → `ttf-ms-fonts` (AUR).
- **QML theme singletons (`Color`, `Style`) are undefined during early binding evaluation.** Direct chains like `Color.menu.background` throw `TypeError: Cannot read property 'background' of undefined` at startup. Wrap every access: `(typeof Color !== "undefined" && Color.menu) ? Color.menu.background : "#fallback"` (and same for Style). Fallbacks must be literals, not another singleton property that may also be undefined.
- **`write_file` can leave a trailing `""", "path">` artifact** (an echo of tool metadata) after the file content. Always run `python3 -m py_compile` / `bash -n` afterwards; on `unterminated triple-quoted string`, trim the trailing lines and re-verify.
- **Ported commands that live under a family dispatcher should also be copied into `blackarch_modules/`** as `<name>.py` modules so the dispatcher and direct callers share one implementation; keep the bin entrypoint as a thin shebang wrapper or module-backed script so existing paths keep working.
- **Always run `python3 -m py_compile <file>` after writing a Python port.** Catches syntax errors (including stray trailing garbage from tool output) before execution.
- **Hyprland-dependent scripts fail outside a session.** `hyprctl` requires `HYPRLAND_INSTANCE_SIGNATURE`; guard JSON parsing with try/except and default to empty structures so the script exits cleanly instead of tracebacking.
- **A ported dispatcher should expose `--complete`** printing its subcommand list (one per line) so shell completion can consume it; implement per handler for nested subcommands.
- Always run `bash -n <script>` syntax check after writing a ported script — catches typos like `firejanger` that would silently fail at runtime.
- AUR helper detection: use a case statement checking for yay/paru/trizen/pikaur in order. Split package installation into official repos (`pacman -S`) and AUR (`$AUR_HELPER -S`) phases.
- Sudoers on Arch: use `%wheel` group (not `%sudo` as on Debian). Paths must use `/usr/bin/` (not `/usr/sbin/`) due to merged-/usr.
- `limine-install` may hang waiting for confirmation — copy the EFI binary directly with `cp` to `/efi/EFI/BOOT/BOOTX64.EFI` instead.
- The limine-mkinitcpio-hook regenerates limine.conf on every kernel update — add custom snapshot entries after the hook runs or use a separate config include.
- When porting a bash tool to Python, verify the original's *reached* code path before mirroring it — bash files often redefine a function (second definition wins) or carry a commented-out branch that shows the intended behaviour. See `references/bash-to-python-porting.md`.
- **Deliver the shape that was asked for: a standalone port is ONE self-contained Python file.** When the user asks for a port as a standalone script, leave the bash original untouched and do not also build a thin launcher plus a `<name>.bash-orig` pair — that machinery is unrequested surface. Reserve the launcher wrapper for ports that must stay reachable under their existing command name, because the dispatcher's `blackarch:summary=` scan and the `/usr/sbin` symlink both depend on it. Either way, never overwrite the original in place: that destroys the ability to diff old vs new and forces the caller to learn a new invocation.
- **A port dropped into the dispatcher's bin directory must NOT carry a `.py` suffix.** The dispatcher registers every `blackarch-*` file in that directory as a command and reads its `# blackarch:key=value` headers, so `blackarch-menu.py` appears in `blackarch commands` as a bogus `menu.py` route and gets suggested for typos. Name single commands `blackarch-<name>` and families `blackarch-<group>` (Python shebang, no suffix). Consequence to check after writing: `blackarch commands` shows the intended route and no `*.py` route.
- **Check the shebang before diffing, and invoke each side the way a caller would.** A script with no `#!` line raises `Exec format error` when exec'd directly — a caller reaches it through a shell, which falls back to interpreting it as a shell script. Detect it (`head -1 "$f"`) and run the original as `bash "$f"` while exec'ing the port directly. Symptom of getting this wrong: the harness crashes with `Exec format error`, or worse, runs the *port's Python* through `bash` and reports a wall of syntax errors that say nothing about the port.
- **A family port is one file, and it selects its component from two places.** `blackarch-<group>-<name>` sets the component from `argv[0]` (strip the prefix); `blackarch <group> <name>` sets it from the first argument. Do not create one file per member — the dispatcher glob registers each as its own route. Direct invocations (a menu action calling `blackarch-restart-shell`) still need `/usr/sbin` symlinks, which need sudo: hand that step to the user rather than assuming it. See `references/bash-to-python-porting.md`.
- **A "family" is three different shapes, and a dispatcher must classify them before dispatching.** (1) shared root file with members routed to it; (2) a member that has its own file even though the family has a root (`blackarch installer`, `blackarch-restart-audio`); (3) a member-only family with no root file at all (the theme switchers). Treat a shape-2 member as a subcommand of the root and `--help` forwards into the root's *default action* — a destructive one, in the case of an installer. Treat a shape-3 family name as an executable and it fails to resolve. A family root must never have a default action: it only prints its own help menu. See `references/command-family-dispatcher.md`.
- **A port of a script that was meant to be *sourced* cannot export into the caller's shell.** Print `export KEY=VALUE` lines (values through `shlex.quote`) and document the `eval "$(cmd)"` invocation; verify by sourcing the bash original and eval'ing the port, then comparing the resulting environments.
- **Do not hand-test a new build by invoking the tool as root.** A probe that runs a TTY program as root can create a root-owned config directory (`~/.tool/`) that then permanently blocks the desktop user — the tool looks installed and works for root, and is silently broken for the human. Run the probe as the desktop user, and detect/warn on a root-owned config dir.
- Strip partition suffixes per disk type: nvme/mmc use `p<digits>`, sd/vd/hd use bare trailing digits. A single `p?\d+$` regex mangles `/dev/nvme0n1` into `/dev/nvme0n`.
- **`qs` writes IPC errors to stdout, not stderr, and exits 0 for them.** A wrapper that captures stdout and discards stderr therefore sees `Target not found.` / `Function not found.` / `Too many arguments provided (...)` as ordinary output with a success exit code, while a *transport* failure (no instance, wrong display) exits non-zero. Mirroring `qs` means reproducing the message text, not just the exit code. See `references/quickshell-ipc.md`.
- **QML global singletons (`Color`, `Style`) can be undefined during startup binding evaluation.** Guard every direct property chain with `typeof Color !== "undefined" && Color.<surface>` and a literal fallback; bare `Color.menu.background` throws `TypeError: Cannot read property 'background' of undefined` and breaks the binding.
- **A `--complete` flag on a dispatcher prints its subcommand list** (one per line) so shell completion can consume it without parsing help text; implement per handler for nested subcommands.
- **`hyprctl` request prefixes are easy to get wrong.** `hyprctl -j X` sends `j/X`, `hyprctl X` sends `/X` — the slash is part of the prefix, not the ternary. `f"{'j' if json else '/'}{cmd}"` silently produces `jcmd` and the compositor answers `unknown request`. Verify the wire bytes against the real socket before trusting a hand-written client. See `references/hyprland-ipc.md`.
- **A symlinked command directory breaks a thin launcher.** Blackarch symlinks its whole `bin/` into `/usr/sbin`, which precedes `bin/` on PATH, so `dirname "${BASH_SOURCE[0]}"` yields `/usr/sbin` and `$here/cmd.py` does not exist. Use `readlink -f "${BASH_SOURCE[0]}"`. Symptom: works by absolute path, fails when a sibling script calls it by name.
- **Hyprland's classic `dispatch <cmd> <args>` and `keyword` are dead on 0.56.** Only the Lua form `dispatch 'hl.dsp.<module>.<fn>({...})'` works; the classic form is wrapped as `return hl.dispatch(<args>)` and fails to parse. Reproduce the fallback arms for fidelity, but expect them never to run.
- **Replace a subprocess that only *transports* a call with the native protocol, but keep the caller-visible text identical.** When a bash wrapper shells out to a CLI (`qs ipc call`, `hyprctl`, ...) purely to reach a socket, porting means reimplementing the wire protocol — the observable behaviour is the message plus exit code, not the binary. Read the reference implementation's exact strings from source rather than guessing.
- **`waylandsudo` is a zsh *function*, not a binary, so `subprocess` cannot reach it by name.** It lives in `~/.zshrc` and re-supplies the Wayland session variables after `sudo`. Invoke it as `zsh -c '[ -r "$HOME/.zshrc" ] && . "$HOME/.zshrc" >/dev/null 2>&1 || true; waylandsudo <cmd>'` — `zsh -i` sources the rc but enables interactive options that make it refuse a non-interactive command, and `zsh -c` alone sources nothing. Fall back to `sudo /usr/bin/env KEY=VALUE … cmd` when zsh or the rc is absent. Do NOT use a bare `sudo` for a root command launched from the graphical session: the child loses `WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR`/`DBUS_SESSION_BUS_ADDRESS` and silently cannot reach the compositor or session bus.
- **A helper module dropped next to the dispatcher must not be named `blackarch-*.py`.** The dispatcher registers every `blackarch-*` file in `bin/` as a command, so `blackarch_helpers.py` works (the glob is `blackarch-*` and `_` does not match `-`, but `blackarch-helpers.py` would become a route). Keep the importable core as `<name>_helpers.py` and give the command an extension-less `blackarch-<name>` front end; importers add `sys.path.insert(0, os.path.dirname(os.path.abspath(__file__)))` because these commands are symlinked into `/usr/sbin` and are not a package.
- **A dispatcher-installed command (`blackarch execute`, family members) called inside a subcommand must reference the binary by full path (`/opt/blackarch/bin/blackarch execute`) rather than relying on PATH.** `sudo` and `arch-chroot` drop `/opt/blackarch/bin` from PATH; calling the bare command produces `command not found` even though the file exists. Keep the full path variable at the top of the function (`binary = "/opt/blackarch/bin/blackarch execute"`) and pass it explicitly to any `subprocess` or `run()` call that needs it. This applies to `setup_tpm()` and any other dispatcher subcommand that shells out to a sibling command in `/opt/blackarch/bin`.
- **A `blackarch:key=value` header that existed only in a thin launcher is lost the moment the port drops the launcher.** A standalone port scans the implementation file for metadata, so the command still dispatches but `summary`/`args`/`examples` silently fall through to the first comment line — an ASCII banner, a copyright notice, or `-*- coding: utf-8 -*-`. Run `blackarch commands --check` to enumerate every affected command at once; it reports `Missing metadata summary` per file. See `references/bash-to-python-porting.md` for the triage that separates this from a genuinely missing feature.
- **Before porting a dispatcher, find the real reference and diff the DISPATCH SURFACE, not the file.** The dispatcher is often a thin launcher whose sibling `<name>.bash-orig` is the actual implementation; comparing launcher to port compares a stub to a program. Compare `--help`/exit codes on both sides and field-diff the shared binaries — equal behaviour there means the port is complete, and remaining diffs are metadata. Equal function counts with different names is normal: the port replaces bash-jq plumbing (`commands_json_filter`, `emit_command_records`, `examples_as_lines`, `pipe_values_as_lines`) with native Python, which is not a lost feature.
- **A plugin that execs a helper by absolute path fails silently when the helper is absent.** `blackarch.clipboard`'s `Clipboard.qml` calls `$BLACKARCH_PATH/bin/blackarch-clipboard-paste-text` / `-paste-file` / `-open` through `Quickshell.execDetached`. Those three are bash-only in `old_repo/bin` and are absent from `/opt/blackarch/bin`, so `execDetached` logs `Process failed to start, likely because the binary could not be found` and selecting a row does nothing — the overlay still opens and closes, which reads as a UI bug rather than a missing binary. The paste half also needs `wtype` (or `ydotool`) to synthesise Shift+Insert; `capture.sh` supplies only `wl-paste`/`wl-copy`, so `wl-copy` succeeding proves capture, not the whole feature. Check `ls /opt/blackarch/bin/<helper>` and `command -v wtype` before blaming the QML. The helpers also depend on `blackarch-launch-browser` / `blackarch-launch-editor` / `tensaku-edit`, which may themselves be unported.
- A bootstrap/install script that writes into a chroot must use `arch-chroot` (not bare `systemctl` on the host) for service enabling, and must copy `/etc/sudoers.d` explicitly since `pacstrap` does not preserve it.
- Every filesystem a chrooted step touches needs its own bind mount, not just the ESP. `bind_esp_into_chroot()` fixes the ESP, but the target's `@home` subvolume is mounted at `HOME_MNT` — OUTSIDE the root mount — so `arch-chroot <root> chown -R <user>:<user> /home/<user>` resolves `/home/<user>` to a plain directory in the ROOT subvolume, finds nothing, and exits ENOENT. The run then prints `✓ home copied for <user>` immediately followed by `! could not chown /home/<user> ...`, so the home is root-owned in the new install and nothing fails. Add the sibling `bind_home_into_chroot()` / `unbind_home_from_chroot()` pair and call the unbind in `cleanup_mounts()` before the recursive `umount -R`. The tell in a finished-run log is the pair of adjacent lines — a success line and a chown warning — which reads as cosmetic until you notice the chown was the only thing making the copy usable.
- **`sort | uniq` after a `printf '%s\n'` emits a line for EVERY array slot, including an empty one.** `printf "%s\n" "${!arr[@]}"` with an empty key writes a bare newline, which `sort | uniq` keeps as an empty line — so an empty key surfaces as a real, choosable menu entry. Reproduce it by joining `"\n"` per key and not filtering the empty string.
- **Never write `exit N` (or `os._exit`) inside a function that must return a status.** `os._exit(0)` terminates immediately and silently discards the value `sys.exit(main(...))` was about to deliver, so the command's real status is unreachable and a failed exec looks like success. `return` the code instead; only the `fork`ed child branch may use `os._exit`.
- **A `|| <long-running-command>` in bash runs the command in the foreground, so the caller blocks.** Read `cmd || gui` as "the shell waits for `gui`" and port it with `Popen` + `.wait()` — do not assume a launcher should detach. Getting this wrong produced three successive ports of a one-line toggle before measurement settled it.
- Each harness scenario needs its own rebuilt fixture directory, and the harness must clear stale env vars. Reusing one working directory leaks state between scenarios (a leftover `$HOME` file makes a later case behave like the earlier one), and an inherited variable from a previous scenario silently changes a later one's behaviour. Build per-scenario dirs and explicitly `pop` every harness-controlled variable from the environment.
- `arch-chroot` runs commands as root by default. Calling `yay` or `makepkg` inside it without switching to a non-root user triggers `makepkg: Running makepkg as root is not allowed` (exit 10). Use `runuser -u <builduser>` (or `su -c`) inside the chroot before invoking any AUR helper.
- A bootstrap/deploy step that checks `os.path.isdir(target)` and skips when the directory exists silently misses updated source files. Always sync (e.g. `rsync` without an existence guard), because a tree copy must propagate updates to ports, scripts, and dispatcher files — not only first-time installs.
- `rsync -a` implies `-D` (`--devices --specials`), so sockets/devices in the source tree cause exit 23 (partial transfer). For tree copies that should skip special files the same way a Python `copy_function` skips non-regular files, add `--no-specials --no-devices`. Treat exit 23/24 as a warning (use `try_run` / check exit rather than `run` with `check=True`), and verify the tree entry-point exists as the final pass/fail criterion rather than the rsync exit code alone. Also confirm the destination directory ownership matches the copying user before starting, not just before reading.
- **Replacing `shutil.copytree` with rsync needs `--no-specials --no-devices` to preserve the old skip behaviour, and `try_run` instead of `run`.** `-a` implies `-D` (`--devices --specials`), so a live `.sock` in the tree stops being skipped the way a `copy_function` that rejected non-regular files skipped it; and rsync exits 23/24 for a partial transfer (a vanished file, a skipped socket), which `run()` turns into a fatal `die()` on a copy that mostly worked. Pass `--no-specials --no-devices`, warn on a non-zero exit rather than dying, and let the later check for the tree's entry-point binary be what decides the copy failed. Verify the conversion by running the real argv against the real tree once — a 1.7 GB tree with a live socket transfers clean at exit 0 in seconds, which no argv assertion can tell you.

- **Flattening a module's subcommands into a top-level dispatcher:** insert the module path into sys.path before importing, and map subcommand names to the module's main; guard the import in try/except so a missing dependency doesn't break the whole dispatcher.
- **Never hardcode partition paths (`/dev/nvme0n1p2`, `/dev/sda2`) in scripts.** Discover disks/partitions at runtime (`parted -s -j`, `findmnt`, `blkid`, `cryptsetup`).
- **`findmnt -no SOURCE /` on an encrypted root returns `/dev/mapper/<name>[/@]` — the `[/@]` suffix must be stripped before using the mapper name.** A naive `re.sub(r"crypted$", "", source)` produces `/dev/crypt-2b06eb39[/@]`, which `systemd-cryptenroll` treats as a non-existent block device. Resolve the backing device from `cryptsetup status <mapper>` (`device:` line), not from string stripping of the mapper name. Keep the original hardcoded value as the fallback only when discovery fails.

## Bootloader Options on Arch

- **GRUB** — Most common, feature-rich, but complex config
- **systemd-boot** — Simple, clean, but limited features. Pairs with a UKI in `EFI/Linux`, which it discovers without any loader entry; see `references/uki-boot-image.md`.
- **Limine** — Lightweight, fast, native btrfs snapshot support via `snapshot:` protocol. See `references/limine-btrfs-setup.md` for full setup with snapper integration and the timestamp-label pattern (`efibootmgr -L "Limine-<time>"` / `bootctl --efi-boot-option-description`).
